# Запуск STYX B2B на сервере

Кабинет — один процесс Node.js (`server.js`): страницы клиента и менеджера, API, база SQLite в одном файле, отправка писем. Внешних сервисов, кроме почты и проверки ИНН, нет.

## Что нужно заранее

| Что | Зачем |
| --- | --- |
| VPS в России (Яндекс Облако, Selectel, Timeweb Cloud, REG.RU и т. п.), 1 vCPU, 1–2 ГБ RAM, Ubuntu 22.04/24.04 | 152-ФЗ: персональные данные клиентов из РФ хранятся на серверах в РФ |
| Поддомен, например `b2b.styx-naturcosmetic.ru`, A-запись на IP сервера | адрес кабинета и HTTPS-сертификат |
| Почтовый ящик для отправки (SMTP): хост, порт, логин, пароль | письма с заказами, о регистрации, ссылки сброса пароля |
| SPF и DKIM для домена отправителя (настраиваются у почтового провайдера) | чтобы письма не попадали в спам |
| Ключи проверки организаций (`DADATA_TOKEN`, `DADATA_SECRET`) | поиск организации по ИНН и проверка адреса |
| Уведомление в Роскомнадзор об обработке персональных данных (pd.rkn.gov.ru) и заполненная `privacy.html` | обязанность оператора персональных данных |

## Вариант 1. Docker (рекомендуется)

```bash
# на сервере, один раз
curl -fsSL https://get.docker.com | sh
git clone https://github.com/Vladpryanik11/b2b-styx.git /opt/styx-b2b
cd /opt/styx-b2b/deploy
cp ../.env.example .env
nano .env                        # DOMAIN, APP_URL (обязательно: от него строятся ссылки в письмах), почта, ключи
docker compose up -d --build     # кабинет + HTTPS

# первый менеджер (пароль покажется один раз)
docker compose exec app node server.js create-manager manager@styx-naturcosmetic.ru "Имя Фамилия"
```

Кабинет клиента: `https://ваш-домен/`, кабинет менеджера: `https://ваш-домен/admin`.

Полезные команды (из папки `deploy`):

| Что | Команда |
| --- | --- |
| логи | `docker compose logs -f app` |
| обновить до новой версии | `git pull && docker compose up -d --build` |
| перезапустить | `docker compose restart app` |
| резервная копия сейчас | `docker compose exec app node server.js backup` |
| ещё один менеджер | `docker compose exec app node server.js create-manager email "Имя"` (email клиента не подойдёт; повторный запуск для менеджера меняет ему пароль и закрывает его сессии) |

Данные лежат в `deploy/data`: `styx.sqlite` — база, `backups/` — копии.

## Вариант 2. Без Docker (systemd)

```bash
# Node.js 22.13+ (например, из nodesource), Caddy или nginx для HTTPS
sudo useradd --system --home /opt/styx-b2b styx
sudo git clone https://github.com/Vladpryanik11/b2b-styx.git /opt/styx-b2b
cd /opt/styx-b2b && sudo npm ci --omit=dev
sudo cp .env.example .env && sudo nano .env
sudo mkdir -p data && sudo chown -R styx:styx data
sudo chmod 600 .env
sudo cp deploy/styx-b2b.service /etc/systemd/system/
sudo systemctl enable --now styx-b2b
sudo -u styx node server.js create-manager manager@styx-naturcosmetic.ru "Имя Фамилия"
```

Кабинет слушает только `127.0.0.1:8080` (переменная `HOST` в службе), снаружи доступен через прокси с HTTPS. В Caddy достаточно строк `b2b.styx-naturcosmetic.ru { reverse_proxy 127.0.0.1:8080 }`. Логи: `journalctl -u styx-b2b -f`.

## Как это устроено

- **Учётные записи.** Пароли не короче 8 символов, хранятся только как хэш scrypt, сессия — cookie `HttpOnly`, `Secure`, `SameSite=Lax`, 30 дней. После 10 неверных паролей вход для пары «IP + email» закрывается на 15 минут, с одного IP — не больше 50 попыток входа за 15 минут. Смена пароля или блокировка закрывает все сессии и гасит неиспользованные ссылки сброса. Email для входа меняется только с текущим паролем, на прежний адрес уходит уведомление.
- **Регистрация.** Новый клиент указывает ИНН, имя, email и пароль и даёт согласие на обработку данных (дата согласия сохраняется). Менеджеру приходит письмо; клиент входит только после «Подтвердить» в кабинете менеджера и получает письмо, что кабинет открыт. Отключить проверку: `REQUIRE_APPROVAL=0`.
- **Сброс пароля.** «Забыли пароль?» присылает одноразовую ссылку на час. Для менеджеров — то же на странице `/admin`.
- **Юрлица.** Клиент может добавить ещё юрлицо по ИНН — менеджеру приходит письмо. Реквизиты уже сохранённого юрлица из кабинета не меняются.
- **Заказы.** Номер, цены и скидку считает сервер. Заказ сохраняется в базе, даже если письмо не ушло; в кабинете менеджера видно, ушло ли письмо, и его можно отправить ещё раз. Бланки Москвы и Санкт-Петербурга можно скачать из карточки заказа.
- **Статусы заказа:** Новый → В работе → Отгружен → Завершён (или Отменён). Клиент видит статус в своём кабинете.
- **Резервные копии.** Раз в сутки сервер делает копию базы в `data/backups` и хранит последние `BACKUP_KEEP` (по умолчанию 14). Копии на том же диске не спасут от потери сервера — включите снимки диска у хостинга или копируйте папку `backups` в другое место, например `rsync` по cron.
- **Восстановление из копии:** остановить кабинет, заменить `data/styx.sqlite` файлом из `data/backups`, запустить.
- **Логи** пишутся в стандартный вывод: в Docker ротация 5×10 МБ, в systemd — journald.

## Перед открытием клиентам

1. Заполнить `privacy.html`: реквизиты оператора, хостинг, сроки хранения, email для обращений; согласовать с юристом.
2. Подать уведомление в Роскомнадзор.
3. Создать менеджера, зарегистрировать тестового клиента, подтвердить его, оформить заказ и проверить, что письмо с двумя бланками пришло.
4. Проверить, что письма не уходят в спам (SPF, DKIM).
5. Убедиться, что резервные копии появляются в `data/backups` и копируются за пределы сервера.
