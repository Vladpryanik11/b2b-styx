# STYX B2B — регистрация и личный кабинет

В проект добавлен первый frontend-прототип регистрации и личного кабинета.

## Что уже работает в прототипе

- регистрация по имени, email и паролю;
- поиск организации по ИНН или названию;
- выбор контрагента из ответа DaData;
- сохранение привязки `пользователь → организация`;
- автоматическая подстановка реквизитов организации;
- страницы «Обзор», «Мои заказы» и «Профиль»;
- оформление заказа из каталога: выбор категории прайса, поиск по артикулу/названию, выбор объёма, счётчик количества, корзина с итоговой суммой (корзина переживает перезагрузку);
- способ получения и адрес доставки (по умолчанию подставляется юридический адрес);
- карточка заказа с составом и суммой, кнопка «Повторить заказ»;
- редактирование профиля (имя, email, телефон);
- адаптивная версия для телефона;
- локальное сохранение сессии в браузере для проверки интерфейса.

## Запуск

```bash
DADATA_TOKEN=ваш_токен DADATA_SECRET=ваш_секрет node server.js   # Node.js 18+, зависимостей нет
# открыть http://localhost:8080
```

`server.js` раздаёт страницу и реализует `/api/dadata/party`: берёт токен из переменной окружения `DADATA_TOKEN`, ищет организацию через DaData Suggestions API (`suggest/party`, только действующие) и возвращает клиенту только ИНН, КПП, ОГРН, название и адрес. Токен не хранится в файлах проекта — используйте переменную окружения или файл `.env` по образцу `.env.example` с запуском `node --env-file=.env server.js` (Node.js 20.6+; `.env` в `.gitignore`).

Адрес доставки в заказе:

- `GET /api/dadata/address?query=...` — подсказки адреса по мере ввода (DaData Suggestions, нужен только токен);
- `POST /api/dadata/clean-address` с телом `{"address": "мск сухонска 11/-89"}` — стандартизация адреса (DaData Cleaner, `cleaner.dadata.ru`, нужны токен **и** `DADATA_SECRET`; метод платный — вызывается только по кнопке «Проверить адрес»). Возвращает адрес с индексом и код качества `qc` (0 — распознан уверенно).

Если `DADATA_TOKEN` не задан или сервер не запущен (страница открыта как файл), поиск работает на тестовых организациях с пометкой «тест». Если DaData ответила ошибкой, пользователь видит сообщение «Сервис DaData временно недоступен».

## Подключение DaData

Клиент вызывает backend-прокси:

```text
GET /api/dadata/party?query=...
```

Токен DaData не должен находиться в `app.js` или передаваться напрямую из браузера. Backend должен сам обратиться к DaData и вернуть ответ в формате:

```json
{
  "suggestions": [
    {
      "value": "ООО «Название»",
      "data": {
        "inn": "7700000000",
        "kpp": "770001001",
        "name": {
          "short_with_opf": "ООО «Название»"
        },
        "address": {
          "unrestricted_value": "г. Москва, ..."
        }
      }
    }
  ]
}
```

Если endpoint пока не запущен, интерфейс использует локальные тестовые подсказки для проверки сценария.

## Адреса доставки

У каждого юрлица может быть несколько адресов доставки. Они хранятся в `account.companies[].deliveryAddresses` (`id`, `label`, `address`, `isDefault`) и редактируются в профиле. В новом заказе основной адрес выбран сразу, можно выбрать другой сохранённый или ввести новый с подсказками DaData и сохранить его в профиль. В production список нужно хранить на backend.

## Несколько юрлиц

Один вход может работать с несколькими юрлицами (ООО, ИП одного владельца). Юрлица хранятся в `account.companies[]` (реквизиты + `deliveryAddresses`), выбор в шапке — `account.activeCompanyId` (id юрлица или `"all"` для режима «Все юрлица»). У каждого заказа есть `companyId` и `companyName`. Новое юрлицо добавляется по ИНН из переключателя или из профиля и сразу доступно для заказа. Старые данные с одним `account.company` переносятся автоматически, заказы без юрлица относятся к первому. В production привязку юрлиц к пользователю и проверку прав нужно делать на backend.

## Промокоды

В заказе есть поле «Промокод». Коды и процент скидки заданы в `PROMO_CODES` в `app.js` (сейчас XSIZE и LANDGROUP — по 10% на товары). В заказе сохраняются `subtotal`, `promoCode`, `discountPercent`, `discount` и итоговый `total`. В production список кодов нельзя держать в браузере: код проверяет и сумму пересчитывает сервер.

## Типографика

Шрифт как на styx-naturcosmetic.ru: Montserrat (вариативный, веса 400–700), лежит локально в `fonts/`, лицензия SIL OFL 1.1 (`fonts/OFL.txt`). Базовый текст 15px, подписи не меньше 12–13px, капса нет: кнопки и меню набраны обычным регистром. Акцентный зелёный взят с сайта (#2aaf42); белый текст стоит на более тёмном `--green-button`, чтобы проходить контраст.

## Каталог

Каталог лежит в `catalog.js` и собран из PDF-прайса «Профессионалы. Опт» от 01.10.2026: 156 позиций в разделах прайса, сгруппированных в `CATALOG_GROUPS` («Проф. косметика для термообёртываний и виски-пеленания» и «Ароматерапия и уход»; в группу обёртываний входят также массажные масла с эфирной формулой и холодная и горячая соль), артикулы и оптовые цены как в прайсе, объёмы одного товара сведены в варианты. Исходные строки прайса лежат в `price-2026-10-01.csv` и `price-2026-10-01.json` (колонка «Название в прайсе» хранит написание из PDF). Остатков в прайсе нет, поэтому все позиции помечены `inStock: true`. Для production его нужно заменить на ответ backend, например `GET /api/catalog` в том же формате (`CATALOG_CATEGORIES`, `CATALOG[].variants[] = { sku, volume, price, inStock }`).

## Что нужно сделать для production

Сейчас это frontend-прототип: учетная запись и заказы сохраняются в `localStorage`, чтобы можно было проверить сценарий без backend.

Для production потребуется:

1. API регистрации и входа.
2. Таблицы `users`, `companies`, `user_companies`, `orders`.
3. Хранение паролей только в виде Argon2id/bcrypt-хэша на сервере.
4. Серверная проверка прав пользователя при каждом запросе.
5. ~~Реализация `/api/dadata/party`~~ — сделано в `server.js`; для production нужны HTTPS, rate limit и кэш ответов.
6. Замена localStorage-логики в `app.js` на запросы к API.
7. API каталога с актуальными ценами и остатками; пересчёт суммы заказа на сервере.
8. Ограничение прототипа: в браузере хранится только один кабинет, новая регистрация заменяет прежний вместе с заказами.
